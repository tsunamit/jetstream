# Jetstream

A keyboard-first Electron client for Capy. It browses projects, threads, and conversations; it does not run a shell.

## Run locally on Mac

Canonical development folder: `/Users/ryan/Developer/capy-terminal`. Use Node 22.12+ on this Mac:

```sh
cd ~/Developer/capy-terminal
npm ci
npm run demo
```

Use `/opt/homebrew/bin` on PATH if Node is not active in your shell. Tower is no longer required for implementation or deployment.

Mock mode uses sample data and makes no API calls, even with a saved credential. The header’s **Mode: Live / Mock** selector switches without restarting the app. Live uses the current session credential, otherwise the environment credential or saved key, and opens **Connect** if none exists. Validation failure keeps the previous mode and data. Replies in Mock stay local; real sends still require explicit submit and use queued delivery.

## macOS standalone preview

On an Apple Silicon Mac with Node 22.12+, run `npm ci && npm run pack`. This creates and ad-hoc signs `dist/Jetstream-darwin-arm64/Jetstream.app`. First launch starts in Mock; later launches restore the selected mode from `connection.json` under Electron userData. Live startup validates its credential before showing connected data. This is a local preview, not notarized or published. `--demo` always overrides to Mock; otherwise `--live` or `CAPY_API_KEY` overrides to Live. At startup, environment takes precedence over a saved key but is never saved automatically. A manually entered key becomes the active session credential. Do not package over a running session’s bundle: package in fresh staging and exchange whole bundles, retaining the old one until that session exits.

### Rename compatibility

Jetstream keeps the existing source folder; the name is not a source-directory migration. Stable uses `~/Library/Application Support/Capy Terminal` for both userData and sessionData on macOS, explicitly set before startup. Jetstream Dev retains `~/Library/Application Support/Capy Terminal Dev/profiles/<name>` and never reads stable's profile. Explicit temporary test profiles remain isolated. No config, history, model selection, drafts, encrypted credential files, or Keychain entries are copied or rewritten by the rename.

`product-identity.cjs` keeps the legacy runtime name until Electron initializes encryption, then changes the visible app/menu/About/window name at ready. This ordering is security-sensitive: in pinned Electron 45.4.1, [`PostEarlyInitialization`](https://github.com/electron/electron/blob/v45.4.1/shell/browser/electron_browser_main_parts.cc) loads and joins application code before `PostCreateMainMessageLoop` captures `Browser::Get()->GetName()` as the Keychain account and the service suffix ` Safe Storage`. Thus stable still uses account `Capy Terminal` and service `Capy Terminal Safe Storage`; Dev still uses `Capy Terminal Dev` and `Capy Terminal Dev Safe Storage`. Re-audit that lifecycle before upgrading Electron. The application bundle identifier remains `local.ryan.capy-terminal`, including its existing helper identifiers, and signing stays ad-hoc (`codesign --sign -`). Changing an ad-hoc executable can still trigger macOS access-policy prompts; the rename does not bypass those policies or test against a real Keychain.

Lazy encryption initialization keeps those same names: pinned [Chromium 156.0.8078.100 `KeychainPassword`](https://github.com/chromium/chromium/blob/156.0.8078.100/components/os_crypt/common/keychain_password_mac.mm) stores service/account in static strings; `GetPassword()` later reads those strings, not the current application name. Electron's [`Browser::SetName`](https://github.com/electron/electron/blob/v45.4.1/shell/browser/browser.cc) updates only the overridden name and user agent, not those storage strings. No eager Keychain read is needed for the rename.

Packaging creates a new `Jetstream.app` with a `Jetstream` executable, rather than renaming a signed bundle in place. The integration owner alone stages and verifies signatures/resources, installs the branded target, and atomically replaces the former launch location with a compatibility symlink while retaining its previous bundle. Retain every archive backing a running process; do not start a second stable process during that swap. The old launch location can resolve to Jetstream without moving the source folder or discarding an active session. Reload the installed release by quitting and reopening when convenient.

Run `npm test && npm run dev-test && npm run branding-smoke && npm run dev-smoke` for mocked profile/crypto migration checks and hidden, temporary-profile UI regressions. These checks never unlock real credentials. See [DEV.md](DEV.md) for the explicit **Jetstream Dev.command** launcher; nothing auto-starts.

## Secure connection and mode isolation

Connect validates a manually entered key before changing the session or saved credential. **Remember securely on this Mac** is checked by default. Main-process Electron `safeStorage` encrypts the key using macOS Keychain-backed protection, then atomically replaces `credential.bin` with mode 0600. There is no plaintext fallback, config/localStorage/environment write, shell command or renderer-returned key. Native Keychain access can prompt depending on signing/access settings. If encryption is unavailable, the badge/dialog identify a session-only connection; any previous saved key stays unchanged. Unchecking Remember also leaves an older saved key unchanged. Decryption, corruption or rejected-key failures offer reconnect/forget recovery without echoing credentials. **Forget saved key and disconnect** removes local ciphertext and the active key and enters Mock; it does not revoke the API key at Capy.

Mode/account changes reload only the renderer after main commits the connection, discarding old polling, catalogs, attachment caches, visits, view history and creation forms. Main aborts old reads and rejects stale attachment results. Mock and each API-key identity have separate workspace settings and draft text; rotating a key gets a separate scope. Up to 100 thread drafts per scope survive mode switches in main-process memory, not app quit. Editor undo/selection and navigation history reset on a mode change; keymaps stay independent. Switch/reconnect/forget is blocked during sends, creation and attachment operations, and never automatically retries a POST. The native mode select is keyboard accessible without a competing Vim shortcut.

## Automatic conversation history

Threads stay chronological and land at the newest loaded message. The documented API has no latest/tail parameter: an unqualified messages request returns the oldest page. The client follows forward cursors automatically, in batches of at most five requests, progressively rendering history with **Loading history toward latest** until it reaches the tail. Sparse/tool-only pages continue too. A cold long thread cannot show its actual latest message before this forward chain completes. Normal loading needs no **Load newer** clicks. A 200-page catch-up safeguard pauses with an explicit notice and **Refresh** continuation; repeated/cyclic cursors stop with retry feedback.

The active account/mode renderer caches up to 30 transcripts in memory. Reopening shows cached history immediately and checks the tail. Visible live threads check for updates every 15 seconds, independently of sidebar refreshes. Errors retain the previous complete batch and retry up to three times with exponential backoff or the server’s numeric Retry-After, then offer explicit retry. Thread/mode changes and hidden windows cancel/discard stale loads. Existing message nodes, semantic selections and scroll positions stay stable; appends follow only while already at the bottom without a Visual selection. Earlier/Newer buttons remain exception/retry tools, not the normal path.

`node connection-smoke.cjs` and `node autoload-smoke.cjs` exercise isolated fake-API lifecycle/history behavior. Credential units use an AES-GCM adapter to test encrypted persistence/restart, permissions, corruption, rejection, unavailability and forget. Hidden app tests force secure storage unavailable rather than touching native Keychain. Actual macOS Keychain encryption/decryption, authenticated API behavior and native OS focus are not verified.

## Work tree and new threads

Live sessions use a dedicated work-tree sidebar. **Filters** expands its controls; the **Tree / Activity** selector and **Refresh / retry** stay visible. Sort by activity timestamp, name or status. Filter the current project, all accessible projects, one project, status or text. Archive visibility, counts, section visibility/order and expanded Captain IDs persist. Captains join crew through the API's `captain.jamId`, never title matching. `j/k` moves rows, `h/l` collapses/expands, and Enter or clicking toggles a Captain and opens its conversation. Crew Enter opens the actual thread. The old paged demo navigator stays available; **Work tree** enables the component on sample data.

The main process reads every thread page for every accessible project and every Captain page, then swaps in a complete snapshot. It never silently substitutes a truncated page: repeated cursors, more than 200 pages per collection or a 30-second refresh budget produce an explicit stale/error state (an already-running request can take up to another 15 seconds). While visible, the sidebar refreshes at most once every 60 seconds, without overlapping reads. Hidden windows stop scheduled polls. Manual refresh and reconnect retry remain available. Failed reads retain last-known statuses marked **STALE**, not idle. A two-minute **just finished turn** label appears only after observing working → idle/waiting/failed during this session, not for historical idle threads or across a disconnected/hidden interval. It is not a task-completion claim.

**New thread**, or configurable **Space t n** in navigation/idle composer Normal, opens a form. Choose a real accessible project, cloud size (or project default), catalog model (or server-resolved account default), supported reasoning strength and advertised fast/pro/ultrafast modes. Enter an initial prompt and explicitly press **Create thread**. Creation uses the documented `requestId` dedupe contract; unchanged retries reuse the ID, simultaneous submits are blocked in renderer and main, and errors preserve the prompt/options. Changing options creates a new request ID. Success opens the returned thread with real project/history identity and refreshes the sidebar. Successful non-secret choices persist per project; prompts never persist. Server-side model/plan/size rejection remains authoritative.

The public API accepts explicit device targets, but documents no paired-device/linked-folder discovery or availability endpoint. **Paired device** and **This Mac/current checkout** are disabled rather than guessing IDs, paths or connection state. The model catalog does not advertise daybreak, so that mode is unavailable here. No cost estimate is invented. This client does not create Captains, attach crew, provision local folders or move machines. Live threads/running/needs-you/session-visited Captains now share the actual API source with pickers; historical turn results and persistent live pins remain unavailable. In live mode the results quick opener opens real threads and labels the historical-result limitation.

Work-tree configuration is a separate validated `workspace-<scope>.json` file under Electron userData. Demo has its own scope; live scopes use a SHA-256-derived API-key identity, so a different key gets separate settings even for the same principal. No key or prompt is written. Invalid configuration falls back without rewriting the original; explicit settings changes save atomically. Existing keymaps keep their version, custom leader, overrides and unmaps. A conflict with the new default `tn` activates the existing non-destructive Keymaps repair flow.

`node worktree-smoke.cjs /path/to/screenshots` runs the real API/IPC/renderer lifecycle against an isolated, main-process fake fetch backend, never a real account. It covers hierarchy, paging, filters, activity/stale state, model modes, all cloud sizes, rejected/duplicate/retried creates, history, settings reload, unavailable models and modal input safety. It uses the same hidden/no-activation harness as other suites. Authenticated API and native macOS semantics are not claimed.

## Keyboard

- The reply editor is its own window directly below chat; the navigator is on the left. `Space w h/j/k/l` moves left/down/up/right with the default Space leader. `Ctrl+W`, then `h/j/k/l` remains an alias. Direct `Ctrl+h/j/k/l` moves between these windows, including from composer Insert; it deliberately takes precedence over those editing chords there. Boundaries do nothing. Window navigation preserves the editor's mode, draft and selection instead of sending an implicit Escape. `Space w w` and `gt/gT` cycle navigator → chat → reply, including from idle composer Normal. Unmatched non-leader editor prefixes return to Vim, so `gg` still works.
- `j` / `k`: focus a thread in the navigator. In chat, they move through actual wrapped screen rows and retain the desired horizontal column. A count such as `3j` moves three rows. `Enter` opens the focused thread or current chat image/diagram source.
- `i` focuses the composer in insert mode. Typing `jk` in Insert returns to Normal without leaving `jk` in the draft; an unmatched `j`, a timed-out pair, paste, unrelated fields and prompts keep their text. The escape timing uses the configured sequence timeout (900 ms by default). `Esc` enters composer normal without moving the draft cursor; further `Esc` cancels a pending command/selection or does nothing, retaining composer focus. Use `Ctrl+W`, then `l`, to focus chat. Navigation keys type normally in composer insert.
- `Ctrl+Enter` or `⌘+Enter` queues a reply. `?` opens the shortcuts.
- `Ctrl+O` / `Ctrl+I` go back / forward through committed views in chat/navigator normal mode; in the composer they always belong to Vim. `Alt+Left` / `Alt+Right` and the header buttons do the same. Tab (including Ctrl+Tab) remains focus navigation; terminals that report Ctrl+I as Tab should use the alternative.

View history keeps the last 100 locations for this renderer session, including exact result targets, loaded message pages, scroll, and focus. Drafts stay independent per thread. Picker previews and cancellation do not add history; a new destination after going back replaces the forward branch. History and drafts are not saved on quit. Restoring a view uses cached messages and checks for updates in the background; scroll is best-effort if content changed.

## Keymaps and leader

Open **Keymaps** in the header (default: `<leader>,`). To use Space, enter `<Space>` in the **Leader** field and click **Save keymaps**. Press the keys consecutively: **Space r d**, **Space r t**, **Space r c**. Command+K (Mac) / Ctrl+Shift+K (Linux) is a separate global quick opener, not the leader; it also works from composer insert. Change the leader, sequence timeout, or any action's alternatives, then **Save keymaps**. Changes apply immediately and survive restarts. Empty mapping fields unmap an action; **Reset defaults** repairs everything even if all keys are unmapped. Header buttons, **Edit reply**, **Chat cursor**, **Select text**, **Copy selection**, and standard Tab/Enter activation remain usable without mappings. Help and shortcut hints are generated from active mappings.

This is declarative configuration, not executable Vim/Lua/JavaScript. The main process validates and atomically stores `keymaps.json` in Electron's application-specific `userData` directory, the retained legacy path `~/.config/Capy Terminal/keymaps.json` on Linux. The exact path is shown in Keymaps. This file is separate from demo pins, session drafts/history, and encrypted API credentials; it contains only mappings. Invalid saved JSON/configuration activates defaults without overwriting the bad file. **Keymaps (repair)** stays visible until a successful save/reset. Manual file edits take effect on the next renderer reload or restart.

The file shape is `{ "version": 3, "leader": "<Space>", "timeout": 900, "mappings": { "reply": ["e"], "up": [] } }`. Omitted actions inherit defaults; an empty array unmaps. Version 1 and 2 files migrate to version 3 without rewriting custom bindings, alternatives, leaders, timeouts or unmaps. Exact former Ctrl+W h/l, two-window cycle and Escape-only defaults inherit the new window/leader and jk alternatives once; future version 3 explicit overrides remain explicit. Linux’s old default quick opener moves from Ctrl+K to Ctrl+Shift+K so Ctrl+K can move up; Mac keeps Command+K. Version 1 also migrates exact old defaults: results u → rd, threads t → rt, running r → rr, and line/list up/down gain arrows and Ctrl P/N. Custom leaders, unrelated mappings, custom alternatives, unmaps and timeouts stay intact. A prefix/duplicate conflict aborts migration without touching the saved file, activates fallback defaults with an actionable repair message, and loads the proposed configuration with preserved overrides into Keymaps for repair. Fix the named conflicting action and Save. Actions have fixed scopes defined in the registry, not a persisted global normal mode. The settings form writes explicit alternatives for all actions; reset restores inheritance.

Supported notation:

- Literal character sequences, including case: `gt`, `gT`, `gg`, `dd`, `?`, and `<leader>rd`. The leader is one unmodified printable key, default Space. There is no localleader because there are no buffer-local mapping consumers yet.
- `<C-j>`, `<A-Left>`, `<C-w>h`, `<C-S-j>`; C is Ctrl, A is Alt, S is Shift, M is Meta on macOS, D is the platform primary modifier (Ctrl on Linux, Meta on macOS). Modified Shift remains distinct from the unshifted chord.
- Named keys: `<Space>`, `<Esc>`, `<Enter>`, `<Left>`, `<Right>`, `<Up>`, `<Down>`, `<Backspace>`, `<Delete>`, `<Home>`, `<End>`, `<PageUp>`, `<PageDown>`, F1–F12 where not reserved. Use `|` between alternatives in the UI. Sequences are at most eight keys; angle brackets and a literal pipe mapping are not supported by the UI.

Duplicate bindings and exact-prefix ambiguities are rejected in overlapping scopes, including leader-expanded conflicts. The last valid config remains active when validation or saving fails. Native editing/window shortcuts, Tab, known OS/application chords (including F5/F11/F12), and Linux Meta/Super mappings are rejected with feedback rather than claimed to work. Other system-wide shortcuts can still be intercepted by the user's desktop environment; these are not OS-global registrations.

Navigation mappings apply in navigator/chat and idle composer Normal. Recognized app mappings take precedence there, including configured leader actions, window cycling, pickers and help. Default `i/o/a` remain Vim Insert-entry commands inside the editor; an explicit custom reply mapping is an app binding. Visual, counts, pending operators/registers/literal keys and Insert Ctrl+O commands keep unmodified input engine-owned. Modified window shortcuts and explicit global/send chords remain available without changing editor mode. Chat-only `gd` and editor Ctrl+O/I are never app reference/history commands in the editor. Window commands never capture unrelated input fields, editor search/Ex prompts, dialogs, IME or AltGraph. Picker mappings apply only inside the picker. Dialog Escape and standard button activation remain safety affordances. Held editor keys stay with Vim unless an explicit app binding consumes them; app sends, toggles, leader/multikey commands and pin changes never auto-repeat. An unfinished sequence expires after 250–3000 ms (default 900), or cancels on Escape, mode/context/focus change, pointer interaction, composition, blur, or visibility change. Consumed app leader prefixes are discarded on mismatch/timeout; ambiguous printable non-leader prefixes return to Vim so unbound commands are not lost.

## Pane-local keyboard prototype

The status bar distinguishes **CHAT NORMAL**, **CHAT VISUAL**, **COMPOSER NORMAL**, **COMPOSER INSERT**, and **NAVIGATOR**. There is no separate app-wide normal mode.

The highlighted bottom status line shows mode, focus, project/context, logical line/column or navigator row, pending keys and demo/connection state. Insert is blue, visual is lavender, normal is mint. Long contexts truncate and segments wrap at minimum width. Chat Ctrl P/N, arrows and configured vertical actions move one wrapped screen row, including when held. Composer motions remain engine-owned; navigator/picker move one focused row. The position label still reports semantic logical line/column, not a synthetic newline for each wrap.

Chat navigation projects only semantic Markdown body text. Headers, timestamps, role labels, code toolbars and media controls never become keyboard cursor targets. Synthetic separators connect paragraphs, list items, cells and messages; character motions skip separator-only gaps. Diagrams/images are atomic objects, not SVG labels. Explicitly opening diagram source adds that source text to navigation. Keyboard visual mode paints one CSS Highlight range per body text node, so metadata between messages is never highlighted or yanked; native mouse selection is unchanged. Live media insertion preserves the current body-node anchor, and session/history snapshots restore a matching body text/object anchor within the same message when possible, falling back to a clamped offset if content changed.

- **Chat:** `h/l` move by Unicode grapheme; `j/k` move through wrapped screen rows using neighboring DOM Range geometry and the desired horizontal column. Geometry is fresh on every move; layout/text changes reset that column. No wrap characters are inserted into the projection or copied text. `w/b` move through whitespace-delimited words, `0/$` to logical line boundaries, `gg/G` to the beginning/end, and `{`/`}` to message boundaries. A mint cursor marks the current character. `v` selects characters; `V` selects logical lines; motions extend the selection. `y` copies plain text to the system clipboard, then leaves visual mode. Escape cancels visual selection. `/` opens a scoped text-search dialog; `n/N` repeat forward/backward with wraparound.
- **Rich chat:** code and table cell text participate in cursor movement. Images and rendered diagrams are opaque, outlined objects, not fake editable text. Enter on an image opens its preview; Enter on a diagram opens and focuses its source disclosure. Copy skips object markers and toolbar labels. Native mouse selection, links, media buttons, and Copy code still work. **Copy selection** also supports mouse-selected transcript text.
- **Composer:** CodeMirror 6 with locally bundled `@replit/codemirror-vim` 6.4.0 owns editing. It supports standard small/big-word and line/buffer motions, counts, character find/till/repeats, operator-motion combinations, text objects, character/line/block Visual modes, forward/backward search and n/N, named registers, linewise paste, macros, coherent undo/redo, dot repeat and Insert entry forms. Escape stays in composer Normal; Edit reply enters Insert. Ctrl+O/I/R/D/U belong to the engine here, not app history or transcript paging. Ctrl+Enter/Command+Enter explicitly send from any editor mode; Enter in an Ex/search prompt cannot implicitly send the form.

Each thread retains one editor, including its buffer, undo/redo, marks, selection, mode and scroll. View history restores cursor/mode snapshots without rewinding the current draft. Sending clears only the unchanged original document, including in an inactive thread; edits made during an asynchronous send survive. State is session-only, not restart persistence. The 30,000-character limit rejects oversized edits/pastes atomically. Native copy/paste events remain; Vim registers are engine-local and ordinary yanks do not automatically copy to the system clipboard. System clipboard registers depend on Chromium permissions.

The engine is Vim emulation, not a Vim/Neovim runtime: no Lua, plugins, executable configuration or filesystem/shell access. Local Ex substitution, options, mappings and macros are engine-owned; file/window/script commands report unavailable or unsupported. Ex commands cannot send messages. App keymaps remain declarative version 3. The **Reply: enter composer normal** action configures Escape and literal Insert escape mappings (default `jk`); remap to `jj`, or remove the literal mapping to disable it. Engine handling preserves normal typing when a prefix does not match or times out. Window actions use `<leader>w…`, so changing the leader changes window controls too. Retired custom textarea motion defaults no longer appear in settings; explicit legacy draft mappings remain aliases to engine commands. Custom maps, leaders, timeouts and unmaps are retained. Conflicts with new half-page defaults activate the non-destructive repair form without overwriting the saved file.

**Half-page navigation:** Ctrl+D/U move chat Normal/Visual down/up by half the current visible transcript height, including wrapped rows; the body-only cursor and viewport move together, Visual selection extends and boundaries clamp. Navigator and picker have separate half-page actions using their visible height. All six actions can be remapped/unmapped with active help labels. They are not full-page PageDown/PageUp shortcuts. Ctrl+N/P move wrapped chat rows or navigator/picker rows. These app half-page actions never apply to composer editing, unrelated inputs or dialogs.

Run `node composer-smoke.cjs` and `node halfpage-smoke.cjs` for the new surfaces; all existing regression scripts remain available in hidden mode. No native Mac or authenticated live API coverage is claimed. Quit/reopen the existing installed app when convenient to load an updated build.

## Rich conversations

The transcript renders headings, emphasis, lists, quotes, tables, HTTPS links, inline code and fenced code with **Copy code**. Mermaid flowcharts and sequence diagrams render locally with expandable source. Invalid or restricted diagrams retain their source instead of breaking the conversation. Raw HTML is shown as text, not executed. The shell, picker previews and view history are unchanged.

Message attachments use the documented `attachments[].file` fields. Inline images resolve only against that message's exact file ID, `capy-file:fileId`, or sourcePath; a path is never filesystem access. Supported PNG/JPEG/GIF/WebP attachments load automatically near the transcript viewport, through the authenticated fixed-origin attachment-ticket endpoint and the existing public-DNS-pinned, redirect-blocked, 12 MiB download path. Arbitrary remote URLs remain explicit browser-open actions, not automatic tracking requests. Unsupported files keep Save file; failed or budget-limited images expose Load image · retry. Auto loading never opens a native save dialog.

Preview downloads coalesce by account-generation/thread/file metadata. Main permits two concurrent downloads, at most 32 queued requests and 24 automatic attempts per destination; automatic work stops after 24 MiB completed bytes (with at most one extra 12 MiB in-flight response). Main's preview cache is capped at 32 entries/32 MiB of data URLs. Navigation/refresh cancels outstanding previews; account or mode changes also clear the cache. Near-viewport image decoding preserves body selection, scroll intention and focus. Chat's configurable **open current image / diagram source** action (Enter by default) opens the current semantic image object; Esc closes and restores its cursor/selection and scroll. Each image shows the active open binding and close hint. External links stay disabled in Mock mode.

# Live conversation streaming

**Tool activity** is shown by default, inline in the scrollable transcript. Chat actions or the configurable Space v t shortcut toggles public live tool summaries and committed tool messages. The preference is a local layout boolean, independent of accounts and credentials. It does not fetch history, discard records or change stream acknowledgments. Explicit submit adds a local Sending row before the POST settles. A validated `{id,deduped}` admission receipt changes it to Queued · accepted: this records queue delivery, not confirmation that the agent has started. Prior work can delay pickup; only actual status/run frames animate the working indicator. Known API `queuedAt` metadata is labeled queued (last poll). The composer clears only the unchanged sent document and can immediately accept the next draft after admission. Failed or uncertain sends keep their text and expose an explicit same-clientKey retry; no POST is automatically retried. Duplicate concurrent IPC requests coalesce in main, and replay/HTTP user entries reconcile by clientKey or receipt ID. These send records are session-only and bounded to 1,000; restarting loses uncertain-send retry identity, so reconcile the account transcript before manually resending after a restart.

Live fragments paint while POST and history requests are still pending. An exact delivery-call commit replaces its preview even if older replay has no known HTTP boundary yet; that delivery is labeled history syncing, without adding it to the HTTP pager. Unpositioned replay remains retained and triggers history fallback rather than being silently hidden by a healthy connection. Read receipts stay disabled until that boundary is resolved. An ended connection no longer suppresses polling, and an explicit send replaces an ended stream, without adding another subscription beside a healthy or reconnecting one. Sending and background updates do not move focus or pull a reader away from an existing selection/scroll position.

The visible conversation uses one authenticated SSE fetch in the main process. It stays open across explicit sends. Other sidebar rows use the existing bounded 60-second visible polling, not a connection for every row. The current UI does not select subagent conversations; thread streams request `frames=subagent` to show observed lifecycle counts, not subagent replies or a claim that work is complete.

Committed transcript entries are authoritative. Live text/tool summaries are source previews, coalesced at 100ms, reconciled by delivery call ID/tool ID, and discarded after dropped/aborted turns or run end. Markdown, code, images and Mermaid use the existing safe rich renderer only after commit; incomplete live Markdown never triggers diagram rendering or remote image loading. The compact stream label distinguishes live, reconnecting, offline and polling fallback. HTTP 401/403 or in-stream access revocation stops retries and requires explicit account reconnection. Refresh history remains available. Stream cursors are main-process session memory, bounded to 200 scoped thread cursors; cold app restart reloads history/replays again.

The main process fixes the origin to `https://api.capy.ai`, refuses redirects, validates subscriptions, allowlists public event fields, excludes tool arguments/results and error bodies, and sends one acknowledged IPC batch at a time with at most 1 MiB queued behind it. Frames are capped at 512 KiB; previews have at most eight active delivery calls and 200,000 characters per call. Over-limit previews wait for the committed transcript rather than rendering unbounded text. Replay records stop at 3,000 entries or 6 MB per cached conversation; oversized/protocol-invalid frames and replay budget limits visibly fall back to paginated history/polling instead of reconnecting forever. The existing HTTP pager keeps its separate 200-page safeguard. Partial streamed records disclose that they are incomplete and trigger full HTTP hydration. The renderer has no network permission or API key. The pager contains HTTP records only. Disjoint replay is deferred until that boundary exists; timestamps and tool call IDs are not invented ordering cursors. Navigation and hide/show cannot discard an acknowledged record before its scheduled paint. HTTP copies remain authoritative over intentionally partial stream copies. Forbidden access blocks only the affected thread; unauthorized blocks the account until explicit reconnection.
